# 午前問題(過去問)の作成マニュアル — AI向け

このドキュメントは、AIアシスタント(Claude/GPT/Gemini等)が本リポジトリに
応用情報技術者試験の午前問題データを追加するための完全な手順書である。
**最終成果物のJSON契約がすべて**であり、途中の作り方(チャンク経由/直接執筆)は
どちらでもよい。午後問題は [pm-authoring.md](./pm-authoring.md) を参照。

---

## 0. 大原則(MUST)

1. **実在するIPA過去問のみを収録する。** 問題文・選択肢・正答・分野(T/M/S)は
   [IPA公式の過去問題ページ](https://www.ipa.go.jp/shiken/mondai-kaiotu/)で公表されている
   PDFから**逐語転記**する。問題の創作・推測補完は禁止
   (学習者が本番と異なる内容を覚えてしまうため)。
2. **正答と分野は必ず公式解答例PDF(`<code>_ap_am_ans.pdf`)から取る。**
   AIが自分で解いて正答を決めてはならない。
3. `explanation`(解説)と `point`(初学者ポイント)は**アプリ独自のコンテンツなので自作する**。
   ただし後述の文体規約に従うこと。
4. 1回分は**80問完成させてから登録する**。模試機能はその回の80問を掲載順で
   通し出題するため、欠けがあると模試が不完全になる。

## 1. 成果物の契約

### 1.1 ファイル

```
src/data/exams/<examId>.am.json        … 問題データ本体
public/figures/<examId>/am-qNN.png     … 図表画像(図がある問題のみ)
```

### 1.2 examId の命名規則

原則は `<西暦>r<令和年2桁><a|h>` — `a`=秋期、`h`=春期(haru)。
令和2年度は春期試験が取りやめられ、代わりに10月試験として実施されたため、
IPA公式ファイル名に合わせて例外的に `2020r02o` (`o`=October)を用いる。

| examId | label |
|---|---|
| `2025r07a` | `令和7年度 秋期` |
| `2025r07h` | `令和7年度 春期` |
| `2022r04a` | `令和4年度 秋期` |
| `2020r02o` | `令和2年度 10月` |

### 1.3 トップレベル構造

```json
{
 "examId": "2025r07a",
 "label": "令和7年度 秋期",
 "source": "出典: 令和7年度 秋期 応用情報技術者試験 午前問題(IPA 独立行政法人情報処理推進機構)",
 "am": [ /* AmQuestion × 80 */ ]
}
```

### 1.4 AmQuestion のフィールド仕様

型定義の正本は `src/data/types.ts` の `AmQuestion`。

| フィールド | 型 | 必須 | 仕様 |
|---|---|---|---|
| `id` | string | ✔ | `<examId>-am-<NN>`。NNは2桁ゼロ埋め(`01`〜`80`) |
| `examId` | string | ✔ | 親と同一 |
| `number` | number | ✔ | 問番号 1〜80 |
| `text` | string | ✔ | 問題文(逐語)。末尾の「〜はどれか。」まで含む |
| `choices` | string[] | ✔ | ア・イ・ウ・エの順で4要素。**記号(ア等)は含めない**(UI側で付与)。例外: `choicesInFigure: true` の場合のみ `[]` 可(実行時に「(図のア)」…が自動合成される) |
| `answer` | number | ✔ | 正解の添字 0〜3(0=ア, 1=イ, 2=ウ, 3=エ)。**公式解答例から転記** |
| `major` | "T"\|"M"\|"S" | ✔ | 大分類。**公式解答例から転記**(T=テクノロジ, M=マネジメント, S=ストラテジ) |
| `middle` | string | ✔ | 中分類。§1.5 の22分類から選ぶ(自由記述禁止) |
| `figure` | string | 任意 | 図表画像のパス `figures/<examId>/am-qNN.png`。図がある問題のみ |
| `choicesInFigure` | boolean | 任意 | 選択肢自体が図中にある場合のみ `true` |
| `explanation` | string | ✔ | 解説(自作)。§3.2 の文体規約に従う |
| `point` | string | ✔※ | 初学者ポイント(自作)。型上は任意だが**収録済みの午前問題全問に存在**。§3.3 の規約に従う |

### 1.5 middle の許容値(この22個のみ。正本: `src/data/types.ts` の `MIDDLES_BY_MAJOR`)

- **T**: 基礎理論 / アルゴリズムとプログラミング / コンピュータ構成要素 / システム構成要素 /
  ソフトウェア / ハードウェア / ユーザーインタフェース / マルチメディア / データベース /
  ネットワーク / セキュリティ / 開発技術
- **M**: プロジェクトマネジメント / サービスマネジメント / システム監査
- **S**: システム戦略 / システム企画 / 経営戦略 / 技術戦略 / ビジネスインダストリ /
  企業活動 / 法務

majorとmiddleの対応は上の表に従うこと(例: middle「セキュリティ」なら major は必ず "T")。
公式解答例にはT/M/Sしか載っていないため、middleは問題内容から判断して付与する。

## 2. 転記の表記規約(MUST)

収録済みの午前問題で統一されている規約。新規追加も必ず揃えること。

1. **読点は半角カンマ `,`**。IPA原文の全角「，」は `,` に正規化する。
   「、」は使わない。句点は「。」。
   - 例: `図のように16ビットのデータを4×4の正方形状に並べ,行と列に...`
   - 既知の例外: `2022r04a` のみ歴史的に全角「，」のまま収録されている(修正不要)。
     **新規追加は必ず `,`** に統一すること。
2. **記号はUnicodeで原文の見た目を再現**: × ÷ ≦ ≧ ≠ → 等。
   上付き・下付きはUnicode文字(²、₀等)があれば使い、なければ `2^16` `C0` のように書く。
3. **選択肢の並びは原文どおり**(数値選択肢の昇順掲載も原文のまま)。
4. **改行**: 問題文中の改行は原則詰めて1段落にする。表形式の情報が問題文に
   埋め込まれている場合は図表画像(`figure`)に切り出す。
5. **「表を参照」する問題**: 表・コード・図はすべて `figure` の画像にする。
   テキストで無理に再現しない。

### ア〜エの参照について(シャッフル機能との関係)

アプリは選択肢の並びを毎回シャッフルする機能を持つ(`src/data/index.ts` の
`canShuffleChoices` が可否を自動判定)。転記時の注意:

- 問題文や選択肢が「図のア」「aはウ,bはイ」のように**記号を参照する問題は
  そのまま逐語転記してよい**。シャッフル対象から自動で外れる。
- `explanation`/`point` の中で選択肢を「アは〜なので誤り」のように**単独の記号で
  参照するのはOK**(シャッフル表示時に記号が自動で振り直される)。
- ただし `explanation`/`point` に**範囲参照「ア〜エ」を書かない**こと。
  書くとその問題がシャッフル対象から外れてしまう(振り直しで意味が壊れるため)。

## 3. 解説・ポイントの執筆規約

### 3.1 出典と創作の境界

- `text`/`choices`/`answer`/`major` = **逐語転記**(創作禁止)
- `explanation`/`point`/`middle` = **自作**(ただし技術的に正確であること)

### 3.2 explanation(解説)

- 常体(だ・である調)。目安80〜450字、中央値150字前後。
- 構成: ①正解の根拠 → ②「よって〜が正しい。」 → ③主要な誤答肢がなぜ違うか(簡潔に)。
- 例(実データ):
  > 行と列の2方向にパリティを付ける水平垂直パリティでは,1ビット誤りが生じると誤った行と列が1つずつ特定でき,その交点のビットを反転して訂正できる。訂正できるのは1ビットまで。よってアが正しい。2ビット以上の誤りでは交点が特定できず訂正できない。
- 計算問題は途中式を示す。

### 3.3 point(初学者ポイント)

**「用語=短い説明」形式を推奨。** この欄は用語ノート機能の辞書生成
(`scripts/build-terms.ts` の point-pair 抽出)の源泉になっており、
`用語=説明` の形で書くとそのまま単語カードになる。

- 例: `2次元パリティ=1ビット訂正・2ビット検出。誤った行と列の交点で位置を特定する。`
- 例: `エクスプロイト=脆弱性の悪用`
- 複数ペアは「。」区切り: `UDP=コネクションレス・高速・信頼性なし。TCP=コネクション型・信頼性あり。対で覚える。`
- 目安30〜120字。語呂・対比・覚え方の一言を歓迎。
- 「〜と区別」のような対比の補足は説明側に書く(=の左辺は用語名だけにする)。

## 4. 図表(figure)の作成規約

1. パス: `public/figures/<examId>/am-qNN.png`(NNは2桁ゼロ埋め)。
   JSONには `"figure": "figures/<examId>/am-qNN.png"` と書く(`public/` は含めない)。
2. 元PDFのページ画像から該当範囲を切り出す。解像度はページ画像200dpi相当から
   の切り出しで十分(既存図70枚の実測: 幅590〜1250px、中央値1245px)。
3. **品質基準(最重要): 「この画像だけで問題が解けるか」を1枚ずつ確認する。**
   過去に表の右端が切れて解答不能になった事故がある(令和5秋 問30)。
   表の全行全列・凡例・単位・注記が入っていること。
4. `choicesInFigure: true` は「ア〜エの選択肢そのものが図中に描かれている」
   問題だけに使う。このとき `choices: []` でよい(UIが「(図のア)」…を合成する)。
   図中にア〜エのラベルが実際に見えることを確認すること。
5. 切り出しツールは何でもよい(macOSなら `sips`、他環境ならPython PIL等)。

## 5. 作成手順(2通り)

### 方法A: 直接JSONを書く(他AI・非macOS環境向けの推奨)

1. PDFを取得:
   ```bash
   npm run fetch-exam -- <examId> https://www.ipa.go.jp/shiken/mondai-kaiotu/<年度ページ>.html
   # 例: npm run fetch-exam -- 2026r08h https://www.ipa.go.jp/shiken/mondai-kaiotu/2026r08.html
   # → data-src/pdf/<examId>_ap_{am,pm}_{qs,ans}.pdf
   ```
   ネットワークが使えない環境では、人間にPDF(問題+解答例)の提供を依頼する。
2. 問題PDFを読む。テキスト層があれば `pdftotext -layout`、なければ
   `pdftoppm -png -r 200` でページ画像化して読み取る(視覚読み取り可能なAIは画像でよい)。
3. 解答例PDFから80問分の正答(ア〜エ)と分野(T/M/S)を表に起こす。
4. §1の契約どおり `src/data/exams/<examId>.am.json` を書く(80問)。
5. 図がある問題はページ画像から切り出して `public/figures/<examId>/` に置く。
6. §6の登録、§7の検証へ。

### 方法B: 転記チャンク+組み立てスクリプト(macOS向け・既存パイプライン)

`scripts/extract-am.ts` が組み立て・検証・図表切り出し(sips使用)を行う。

1. 入力を用意:
   - `data-src/work/am_chunks-<examId>/*.json` … 転記チャンク(複数ファイル可、
     ファイル名順に連結)。1要素 = 
     ```json
     {
      "number": 4,
      "text": "問題文",
      "choices": ["選択肢ア", "イ", "ウ", "エ"],
      "middle": "基礎理論",
      "figure": { "page": 5, "top": 0.32, "bottom": 0.55, "left": 0.08, "right": 0.95 },
      "choicesInFigure": false,
      "explanation": "解説",
      "point": "用語=説明"
     }
     ```
     `figure` の数値はページ画像に対する割合(0〜1)。`figure`/`choicesInFigure`/`point` は任意。
   - `data-src/pages/am-<examId>/p-NN.png` … ページ画像(fetch-exam後に
     `pdftoppm -png -r 200` で生成)
   - 解答例PDFにテキスト層がない回は `data-src/work/am_answers-<examId>.json` に
     手動転記: `{ "1": {"answer": "ア", "major": "T"}, ... }`(80問分)
2. 実行:
   ```bash
   npm run extract-am -- <examId> "<label>"
   # 例: npm run extract-am -- 2026r08h "令和8年度 春期"
   ```
   スクリプトが検証する項目: 解答例が80問分あるか / 問番号の重複 /
   choicesが4個(choicesInFigure除く) / explanationの存在。

> 注: `data-src/` のPDF・ページ画像・転記チャンクはgitignore対象(コミットしない)。
> コミットするのは `src/data/exams/*.am.json`、`public/figures/**`、および
> 手動転記した正答キー `data-src/work/am_answers-*.json`(これだけ例外的にコミット対象)。

## 6. アプリへの登録(手動・必須)

`src/data/index.ts` に2行追加する:

```ts
import r2026h from "./exams/2026r08h.am.json";   // ← import追加

export const EXAMS: ExamData[] = [
  normalize(r2026h, []),                          // ← 配列に追加(新しい回を先頭側に)
  normalize(r2025a, r2025aPm.pm),
  ...
];
```

登録するとアプリ全体に自動反映される:
分野別演習の試験回チップ / 模試の回選択 / 分析の集計 / 用語ノートの辞書対象。

登録後、**用語辞書を再生成する**(新しい回の用語・出現索引が辞書に入る):

```bash
npm run build:terms
# → src/data/terms.json と src/data/term-index.json が更新される(コミット対象)
```

生成ログの「カード総数」が大きく変動していないか確認し、
新規カードのサンプルを数件読んで §8 の品質基準に照らす。
問題のあるカードは `scripts/term-overrides.json` に `{"<id>": {"drop": true}}` 等を
追記して再生成すれば除外できる(定義文の手書き修正は禁止 — 逐語性テストが落ちる)。

```bash

                   #  - tests/canShuffle.test.mjs: 全問が解答可能(choices4つ or 図中合成)、

                   #  - tests/terms.test.mjs: 辞書の逐語性・索引整合(build:terms後)
```

加えて目視チェックリスト:

- [ ] 図がある全問題について「画像だけで解けるか」を確認した
- [ ] `choicesInFigure` の問題は図中にア〜エのラベルが見える
- [ ] 読点が `,` に統一されている(「、」「，」が混入していない)
- [ ] `point` が全問にあり、「用語=説明」形式が主体になっている
- [ ] `explanation`/`point` に範囲参照「ア〜エ」がない
- [ ] アプリを起動し(`npm run dev`)、分野別演習の試験回チップに新しい回が出る・
      模試でその回を通せる・図表問題が表示できることを確認した

## 8. 過去に実際に起きた不具合(同じ轍を踏まないこと)

| 事故 | 原因 | 現在の防御 | 作成時の注意 |
|---|---|---|---|
| 図中選択肢の問題が解答不能(11問) | `choicesInFigure` で `choices: []` のままUIにボタンが出なかった | 実行時に「(図のア)」…を自動合成+不変条件テスト | 図中にア〜エが実際にあるか確認 |
| 図が欠けて問題が解けない(令和5秋 問30) | 表の切り出し範囲不足 | なし(目視のみ) | **図は1枚ずつ「解けるか」確認** |
| 否定形設問から有害な単語カードが生成 | 「〜ないものはどれか」の逐語切り出しは逆定義になる | build-terms が否定形設問を自動除外 | 問題自体は普通に収録してよい(辞書側で守られる) |
| シャッフルで記号参照が壊れる | ア〜エ参照の問題の並び替え | `canShuffleChoices` が自動除外 | §2の参照ルールに従う |

## 9. 他AIへの依頼テンプレート

別のAIにデータ作成を依頼するときは、このファイルと以下を渡せば足りる:

```
入力: IPA公式PDF2つ(<examId>_ap_am_qs.pdf, <examId>_ap_am_ans.pdf)
出力: docs/am-authoring.md の契約(§1〜§4)に完全準拠した
      src/data/exams/<examId>.am.json(80問)と public/figures/<examId>/ の画像。
制約: 問題文・選択肢・正答・分野は逐語転記。解説とポイントは自作(§3の文体)。
検証: §7 のコマンドとチェックリストがすべて通ること。
```

作成後の登録(§6)・辞書再生成・コミットは本リポジトリ側の作業として実施する。
