## 3層で確かめる

| 層 | 何を守るか | 実行 |
|---|---|---|
| ユニットテスト | ロジックの規則(SRS・マージ・生成物の不変条件) | `npm test` |
| データ整合性 | 880問・図表・用語辞書の構造 | テスト内 + 下記スクリプト |
| 実ブラウザE2E | 画面と保存の結合、回帰 | 使い捨てスクリプト |

出す前に必ず:

```bash
npm test && npx tsc --noEmit && npm run build
```

## ユニットテスト(`tests/*.test.mjs`)

Node標準の `node:test` + `assert/strict`。TypeScriptは `tsx` 経由で直接importします。

```bash
node --import tsx --test tests/vocab.test.mjs   # 単体で回す
```

**書き方の作法**:
- テスト名は日本語で「何が保証されるか」を書く
- localStorage は `withLocalStorage` 方式でスタブ(`tests/vocab.test.mjs` が見本)
- 生成データ(用語辞書)は**不変条件**を検証する
  — 定義が出典の部分文字列であること、索引の相互整合、件数が想定範囲、など
- バグを直したら**そのバグの再現シナリオをテストに固定**する
  (`tests/merge.test.mjs` `tests/review.test.mjs` は全部これ)

## 実ブラウザE2E

Playwright + Chromium が使えます。`dist/` を静的配信して実際にクリックします。

```js
const browser = await chromium.launch({
  executablePath: "/opt/pw-browsers/chromium-1194/chrome-linux/chrome",
});
```

### 落とし穴(実際にハマったもの)

> [!warning] E2Eの注意
> - **`addInitScript` は遷移のたびに再実行される** → 状態の変化を検証したいときは
>   最初に1回だけ `page.evaluate` でシードする
> - 同じハッシュへの `goto` は再マウントしない → `page.reload()` を使う
> - `force: true` のクリックは下の固定タブバーに貫通することがある →
>   `locator.evaluate(el => el.click())` が確実
> - 実績トーストがクリックを遮ることがある

### 定番シナリオ
- **初回ユーザー巡回**: 空データで全ルートを開き、白画面とページエラーが無いことを確認
- **保存の確認**: 操作後に `localStorage` を読んで、期待した形で保存されたか検証
- **モバイル幅**(390〜420px)で横スクロールが漏れていないか

## データ整合性チェック

問題を追加したら、次を機械的に確認します(スクリプトは使い捨てでOK)。

- 全問の `answer` が0〜3、`choices` が4件(図中選択肢を除く)
- 問番号1〜80が欠番・重複なし、IDが一意
- `figure` の参照先が実在する
- 用語辞書: `defQid` が実在、定義が出典の部分文字列、索引のIDが実在

チェックリストの正本は [[am-authoring#7. 検証]] です。
