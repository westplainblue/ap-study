## セットアップ

```bash
npm install
npm run dev        # 開発サーバー(http://localhost:5173)
```

Node 22 系を想定。ビルドは `npm run build`(出力は `dist/`)。

## npmスクリプト

| コマンド | 用途 |
|---|---|
| `npm run dev` | 開発サーバー |
| `npm run build` | 本番ビルド |
| `npm test` | ユニットテスト(全件) |
| `npm run typecheck` | 型チェック(`tsc --noEmit`) |
| `npm run build:terms` | 用語辞書の再生成(問題を追加したら必須) |
| `npm run build:calc` | 計算ドリルのテーマ索引の再生成(問題を追加したら必須) |
| `npm run codex-bridge` | AIチャット用ローカルブリッジ |
| `npm run fetch-exam` | IPAから過去問PDFを取得 |
| `npm run extract-am` | 転記チャンクから問題JSONを組み立て |

## ソースの歩き方

```
src/
  main.tsx / App.tsx     起動・ルーティング(HashRouter)・起動時の導出処理
  pages/                 画面(1ルート = 1ファイル)
  components/            出題プレイヤー・カード・チャット等
  lib/                   ロジック(ここが本体)
  data/                  問題・用語の静的データと問い合わせ関数
  styles/global.css      デザイントークンと共通クラス
scripts/                 データ生成・ブリッジ
tests/                   ユニットテスト(node:test)
docs/                    このVault
```

### `src/lib` の地図

| ファイル | 責務 |
|---|---|
| `progress.ts` | **保存の中心**。ProgressState・記録・復習キュー・マージ |
| `srs.ts` | 間隔反復の純粋ロジック(ドリル上限・遅延保持率) |
| `vocab.ts` | ことば帳の導出・採取・箱遷移 |
| `run.ts` | 演習の中断・再開 |
| `choiceShuffle.ts` | 選択肢シャッフルと記号の読み替え |
| `modeStats.ts` | モード別の集計 |
| `achievements.ts` | 実績の判定 |
| `sync.ts` | クラウド同期 |
| `ai*.ts` | AIチャット・採点・マーク・履歴 |

> [!tip] 迷ったら `progress.ts` から読む
> 保存されるものは全部ここを通ります。データの意味は [[データモデル]]。

## 書き方の作法(このリポジトリの流儀)

- **コメントは日本語**。「何をしているか」ではなく**「なぜそうしたか」**を書く
- ロジックは `lib/` に純粋関数で置き、localStorage の読み書きは薄いラッパに分ける
  (→ テストしやすくなる。`vocab.ts` が見本)
- UIは**インラインstyle + `global.css` の共通クラス**(`.card` `.list-row` `.chip-toggle`
  `.bar-track/.bar-fill` `.modal` `.banner` `.choice`)。CSSフレームワークは入れない
- 新しい画面は `pages/` に1ファイル、`App.tsx` にルート追加。
  **タブバーは増やさず**ホームのメニューに入口を作る(→ [[決定記録]])。
  モードを足したときは **`components/SideNav.tsx`(PCの左サイドバー)にも**追加する
- 破壊的な操作(データ全消し・上書き)には確認ダイアログを必ず置く

### PC対応の作法

画面幅の分岐は**CSSだけ**で書きます(JSでウィンドウ幅を見ない ＝ リサイズや初回描画で
ちらつかない)。1024px未満では下の3つは素通しになるので、**モバイルの見た目を気にせず**付けられます。

| クラス | 使いどころ |
|---|---|
| `.pc-wide` | ページ全体を最大1180pxに広げる(2カラムを使うページの外枠) |
| `.pc-split` | 左右2カラム。`.pc-split-sticky` を子に付けると片側を画面内に固定 |
| `.pc-grid-2` | 一覧を2列に(項目が10個以上あるとき有効) |
| `.pc-hide` | PCでは不要な要素を隠す |
| `.kbd-hint` | キー操作のヒント(PCかつマウス環境のときだけ表示) |

> [!warning] `.pc-split` の子はモバイルで「縦に積まれる」だけ
> 1024px未満では素通し(`display: block`)なので、**PC専用の右カラムは
> 自分で `display: none` にする必要があります**。忘れるとモバイルで
> 中身がそのまま下に表示されます(模試の一覧で実際に起きました)。

キーボードショートカットを足すときは `lib/keys.ts` の純粋関数を使い、
**修飾キー付き(`isPlainKey`)と入力欄フォーカス中(`isTypingTarget`)を必ず除外**してください。
一覧(`components/ShortcutHelp.tsx`)への追記も忘れずに。

### アニメーションの作法

`global.css` 末尾の「モーション」節にまとめてあります。3つの制約を守ってください。

- **120〜200ms、移動は6pxまで**。1問ごとに何十回も繰り返す画面なので、長い演出は
  そのまま待ち時間になります
- **読む対象(問題文・解説)の位置を動かさない**。動かすのは不透明度が基本
- **ホバー効果は `@media (hover: hover) and (pointer: fine)` の中に書く**。
  タッチ端末ではタップ後も効果が残り、誤解を生みます

`prefers-reduced-motion: reduce` の一括停止は既に入っているので、**個別対応は不要**です
(ただし JS でアニメーションを書く場合は自分で `matchMedia` を見てください)。

> [!warning] インラインstyleの `display` に注意
> `.pc-grid-2` は `display: grid` を当てるので、同じ要素にインラインで
> `style={{ display: "flex" }}` を書くと**インライン側が勝って2列になりません**。
> レイアウトの display はクラス側に寄せてください。

テキスト列の幅(`--read-w: 720px`)は広げないのが方針です。理由 →
[[決定記録#PCでは本文を太らせず、余白で「横に並べる」]]

### やってはいけないこと

> [!danger] 触ると壊れるところ
> - `ap-study:ai`(APIキー)を同期・エクスポートに混ぜる
> - `attempts` を書き換える(追記専用。集計はすべてここから導出している)
> - 復習・ことば帳のエントリを **delete** する(同期で復活する → 墓標を使う)
> - 問題JSON(`*.am.json`)の逐語転記部分を編集する(契約は [[am-authoring]])
> - `window.confirm` / `alert` / `prompt` を使う(iOSのホーム画面起動や一部ブラウザでは
>   **表示されずに false が返り、ボタンが無反応に見える**。模試の採点ボタンで実際に起きた。
>   確認は `components/ConfirmDialog` を使う)
